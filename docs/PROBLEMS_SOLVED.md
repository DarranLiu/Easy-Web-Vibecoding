# 曾经解决过的问题

这页不写版本流水账，只说实际遇到过什么，以及最后怎么处理。

| 当时的问题 | 现在怎么做 |
| --- | --- |
| 浏览器一关，AI 任务也跟着没了 | 任务放在 tmux 中运行。浏览器只是远程屏幕，断网和后端重启都不会杀任务。 |
| 页面看起来像普通网页，不像工作软件 | 紧凑的工作区树、可收起任务面板和统一工具栏，让原生终端居中；可选玻璃与动效同时考虑无障碍设置。 |
| 某些 Windows 电脑显示方框或乱码 | 把终端等宽字体和符号字体放进项目，由网页自己加载，并保留跨平台字体回退。 |
| 深色模式里 Codex 输入区变成浅底浅字，几乎看不见 | 由 xterm 自动修正低对比度文字，保留程序原有背景；主题变化同步所有分屏。详见 [v0.1.2 修复说明](releases/v0.1.2.md)。 |
| 鼠标滚轮只翻 AI 应用自己的页面，普通终端历史翻不到 | 区分交互式 TUI 和普通 Shell。前者把滚轮交给应用，后者驱动 tmux copy-mode 历史。 |
| Codex 右上角显示黄色 `[2/2]`，明明还有内容却翻不上去 | 全屏 Codex 使用原生滚轮报告，不再浏览旧的 tmux 快照或整页跳；内联模式保留 tmux 历史，包装进程和短窗口也有覆盖。 |
| 开启选字后不能滚动，触控板轻划又跳得太远 | 选择模式只拦截点击和拖拽，不再拦截滚轮；每个分屏分别累积触控板的小幅移动。 |
| 一个页面只能看一个终端 | 增加最多四格分屏、方向切换、可拖动分隔线、位置交换和独立重连。 |
| OpenCode 按钮实际启动了别的程序 | 从前端类型、后端命令到可执行文件探测都拆开，增加了独立契约测试。 |
| 普通终端里能看到的新 Codex 模型，网页启动时看不到 | 网页复用配置的共享程序入口，跟随最新指向、保留本机模型目录配置并阻止误连旧守护进程。模型可用性仍取决于原生工具、提供商和账号。 |
| 手动 `codex resume` 又连接旧后台 | 网页 Shell 和受支持的子进程保留启动保护，明确连接旧后台的命令会被拒绝，不悄悄更换服务路由。 |
| 重启后只出现 `resume`，没有进入原对话 | 等待回到原 Shell，按记录的会话 ID 恢复，观察到原会话加载才算完成，不把未确认的恢复说成成功。 |
| 更新一个窗口可能影响其它任务 | 仅更新不退出老进程；明确更新并恢复时只针对所选窗口，退出前检查兼容性，不重启其它分屏。 |
| 旧更新失败看起来像当前安装仍然失败 | 安装与恢复分别记录；历史失败已被新安装覆盖，也不表示历史恢复已经成功。 |
| 切换工作区意外改变当前分屏 | 导航与按设备保存的屏幕布局分开，可跨项目分屏。 |
| 三窗重新分配后出现空白第四格 | 按窗格模型定位，不再依赖混有分隔条的 DOM 第一个节点。 |
| Codex 输出时输入底色频闪 | 区分自动跟随与手动看历史，短暂重绘保留已确认底色，相同尺寸不再额外整屏刷新。 |
| Ctrl+C 复制时误取消程序 | 网页 Ctrl+C、Ctrl+Shift+C 和 Mac Cmd+C 只复制选区；没有选区或复制失败也不发送中断，中断需要单独按钮并确认。 |
| Codex 底栏内容被终端高度裁掉 | 把账号额度移到终端外的一行独立区域，终端本身只保留模型、状态和上下文。 |
| 用量条太抢眼，而且多个分屏一起显示 | 改成一条很细的进度条，只在当前聚焦的 Codex 分屏显示。 |
| 网页一直显示旧百分比，桌面端已经变了 | 由服务端返回权威的下一次刷新时间，前端不再自己叠加一层缓存时钟。 |
| 多个页面和两个后端可能同时查询用量 | HTTP/HTTPS 进程共用文件锁与缓存；页面不可见或焦点不在 Codex 时不调度。 |
| 手机软键盘弹出后挡住输入位置 | 根据 Visual Viewport 动态重算终端高度，并在键盘动画结束后再校正一次。 |
| 手机切换会话每次都要重找 | 标题展开最近会话，单终端快速切换；原生命令菜单加方向和确认键，不开键盘也能操作菜单。 |
| 中文输入法偶尔丢字 | 单独处理 IME composition 生命周期，不把正在合成的中文误当成普通按键。 |
| 复制在 HTTP 局域网页面不可用 | HTTPS 下用 Clipboard API，普通 HTTP 下保留受控的兼容复制路径。 |
| 原始 TCP 隧道后面看到的来源 IP 全是本机 | 支持通过反向代理恢复来源 IP；无法恢复时按客户端 ID 和设备信息计数。 |
| Token 出现在 WebSocket 或下载 URL 中 | 登录后改用服务端签名、带有效期的 HttpOnly 会话凭据；原始 Token 不进入浏览器存储、URL、历史和默认访问日志。 |

这些处理有一个共同原则：终端是工作工具，应该稳定、可恢复、少打扰，不能要求用户记住一堆特殊操作。
