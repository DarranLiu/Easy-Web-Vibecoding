# v0.3.0: Compact workbench and saved screens

## English

Run Claude Code, Codex, OpenCode and shells in your browser with saved multi-screen splits, session recovery, hot updates, file uploads and previews, resource monitoring, and mobile controls.

### What changed

- The new workbench puts workspaces on the left, screens at the top and frequently used tools next to the active terminal. Desktop controls and fonts are more compact; saved font choices remain unchanged and mobile controls retain larger touch targets.
- Each named screen holds up to four panes. Rename/reorder screens, move panes between them, and see where a session is already open. Screen layouts are associated with the shared Token and selected profile, with separate desktop/mobile layouts.
- Browser reopening restores the saved screen and splits. Layout conflicts have an explicit recovery flow and a local journal; profiles are not separate security accounts.
- Look up an exact conversation ID, copy its ID, rename or move a session, and change its supported permissions through a confirmation flow. Completed replies can mark inactive panes/screens as unread; focusing the pane clears its mark.
- Upload reference files, insert their paths without submitting a prompt, or preview a path as a directory, document, table, image, media file, PDF or sandboxed HTML.
- Codex quota moved from pane-bottom bars to a compact toolbar battery with a relative reset countdown. Server-side shared caching still bounds account reads.
- CLI updates and original-session recovery remain explicit operations. Model catalogs follow the selected Codex executable when launching instead of staying pinned to an old web-only list.

### Problems addressed

Lost layouts after reopening, duplicate panes across screens, blocked screen changes after conflicts, missing Chinese input, copy-selection failures, stale agent detection and unclear restoration states have targeted regression coverage. This does not guarantee compatibility with every future CLI version or browser.

### Upgrade safely

1. Back up the checkout, private configuration and state files, including the workspace SQLite database, while the service is stopped or using a consistent database backup.
2. Update the checkout and Python dependencies, then restart only the web service. The systemd example uses `KillMode=process` so detached tmux jobs are not terminated along with the web process.
3. Refresh the browser to load the matching frontend. Use the same Token and layout profile. Do not delete browser site data or state files when upgrading.
4. Existing agent processes keep their running version. Use the version panel to update the shared installation or explicitly restart and restore one selected conversation. Restart can interrupt work and cannot restore an in-progress computation or unsent draft.

`CC_WEB_CODEX_MODEL_CATALOG=auto` is the default; an explicit JSON path remains supported and an empty value disables the override. Reference uploads default to `.cc-web-uploads` beneath `CC_WEB_DEFAULT_DIR`; `CC_WEB_UPLOAD_DIR` may select a different path inside the file allowlist. Keep uploads and all runtime state out of Git.

### Privacy and limits

All 44 README screenshots use the actual new frontend with synthetic sessions, paths, files, versions and hardware. English README previews have English labels; this documentation localization does not claim full product localization. No production transcripts or credentials are included.

Signed expiring cookies, file allowlists, private state permissions and sandboxed previews are retained. This is a shared-token terminal, not an isolated multi-tenant service: authenticated operators have the service user's shell access. See [security](../../SECURITY.md), [deployment](../DEPLOYMENT.en.md), and [update/recovery boundaries](../UPDATES.en.md).

## 简体中文

在浏览器里使用 Claude Code、Codex、OpenCode 和 Shell，支持多屏分屏、会话恢复、热更新、文件上传预览、资源监控和手机操作。

### 这次改了什么

- 换成紧凑的工作台：左侧找工作区和会话，顶部切屏幕，常用按钮围绕当前终端排列。电脑端字号、间距更紧凑，已有字号设置保留，手机按钮仍方便点按。
- 一个屏幕最多四格，屏幕可改名、重排，窗口可跨屏移动；已经打开的会话会标明位置。同一 Token 和档案保存布局，手机、电脑分别恢复。
- 重新打开浏览器会恢复保存的屏幕和分屏。多浏览器修改发生冲突时，有明确恢复入口和本地布局备份，不再默默覆盖；档案名称不是独立用户账号。
- 支持按准确会话 ID 查找、复制 ID、会话改名和移动，以及确认后切换支持的运行权限。未读完成状态显示在窗口和屏幕上，进入对应窗口后清除。
- 参考文件可以上传后插入路径，不自动发送。输入路径可预览目录、Markdown、JSON、CSV、图片、音视频、PDF 和受隔离的 HTML。
- Codex 额度改为顶部小电池和相对重置倒计时，不再给每格放进度条；后端仍共享缓存，限制实际请求频率。
- 保留一键更新和原会话恢复；新启动 Codex 时跟随选定程序刷新模型目录，不再固定使用旧的网页列表。

### 解决过的问题

针对重开后丢布局、同一窗口出现在多个屏幕、布局冲突后无法切屏、中文漏字、选字复制失败、程序识别过时和恢复结果不明确等问题补充了回归验证。不承诺所有未来 CLI 版本和浏览器都没有兼容问题。

### 怎么升级

1. 备份代码、私有配置和状态文件，包括工作区 SQLite 数据库；数据库应在服务停止时备份，或使用一致性备份方法。
2. 更新代码和 Python 依赖，只重启 Web 服务。systemd 示例的 `KillMode=process` 用于避免连带结束 tmux 任务。
3. 刷新网页加载配套前端，使用原 Token 和布局档案。不要清空浏览器站点数据和状态文件。
4. 已启动的 AI 程序仍运行旧版本。需要时在版本面板更新共享安装，再明确重启恢复所选会话。恢复的是对话，不是执行中的计算，也不保证保留未发送草稿。

`CC_WEB_CODEX_MODEL_CATALOG` 默认是 `auto`，也可以指定 JSON 路径或用空值关闭覆盖。参考文件默认存入默认目录下的 `.cc-web-uploads`；可用 `CC_WEB_UPLOAD_DIR` 改为文件白名单内的目录。上传文件和运行状态都不要提交到 Git。

### 隐私与边界

主页的 44 张中英文图片全部由新前端和虚构演示数据生成，不使用真实终端记录、服务器资料或凭据。英文截图已本地化，但不代表整个产品已实现完整英文界面。

保留签名 Cookie、文件白名单、私有状态权限和隔离预览。这仍是共享 Token 的远程终端，不是多租户隔离服务；登录者拥有服务用户的 Shell 能力。请同时阅读[安全说明](../../SECURITY.md)、[部署说明](../DEPLOYMENT.md)和[更新与恢复边界](../UPDATES.md)。
