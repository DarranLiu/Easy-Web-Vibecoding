# v0.1.3: Terminal History Scrolling

## English

### What was wrong?

Codex could stop scrolling at a yellow tmux marker such as `[2/2]`, even though earlier conversation content still existed. That marker describes tmux's current history view, not the number of messages in Codex.

The old routing assumed that programs without mouse reporting used ordinary terminal history. Fullscreen Codex can instead keep its transcript inside the application. Entering tmux copy-mode then scrolls only a snapshot of the current screen. The earlier browser-only tests did not cover that runtime state.

### What changed?

- The backend checks the actual foreground command and inner alternate-screen state. For fullscreen `codex`, it leaves stale tmux copy-mode and sends PageUp/PageDown. Inline Codex and normal shells continue to use tmux history.
- Text selection mode permits wheel reports while still blocking pointer clicks, movement and dragging.
- Small trackpad movements accumulate instead of becoming a whole line each. Each pane has its own remainder, cleared on direction change, a pause, a connection change or switching to application-owned mouse scrolling.
- Ctrl+wheel zoom gestures do not become terminal input. Scrolling an unfocused split does not steal keyboard focus.

Fullscreen Codex uses **page navigation**, not pixel-precise scrolling. This relies on its PageUp/PageDown bindings and a foreground command reported as `codex`; custom wrappers or key bindings can need separate handling. The fix does not recreate messages that an application has already discarded. It does not send prompts, press Enter, change model settings or make model API requests.

### Upgrade

Update the project, restart the **Web backend** using your existing deployment method, then reload the browser. A page refresh alone does not load the changed Python code. WebSocket connections briefly reconnect.

Keep existing tmux sessions running. Before restarting a service or container, confirm that it does not also own the tmux server or agent processes. Do not delete or recreate a container that contains the only copy of your running tasks.

### Verification

Coverage includes selection, touch, trackpad deltas, zoom, split-pane routing and theme rendering. Backend tests cover native Codex history, stale copy-mode, ordinary scrollback and invalid state. Integration tests compile an offline fixture named `codex` and run it in a private tmux server with an empty configuration, without accessing accounts or live tasks.

```bash
CC_WEB_TMUX_TESTS=1 python -m unittest discover -s tests -v
npm ci
npx playwright install chromium
npm run test:browser
```

The integration tests need `tmux` and a C compiler (`cc`). Node.js and Playwright are optional development test dependencies, not server runtime requirements.

## 简体中文

### 解决了什么问题？

Codex 右上角出现黄色 `[2/2]`，再往上滚也不动，但实际上还有更早的对话。这个数字是 tmux 的历史查看位置，不是 Codex 的消息数量。

旧逻辑把“不上报鼠标事件”当成“历史都在 tmux 里”。但全屏 Codex 可以自己管理对话记录，此时 tmux 只能翻当前画面的快照。此前只做浏览器事件测试，没有覆盖这个真实运行状态。

### 这次怎么修？

- 后端检查当前真正运行的程序和屏幕模式。全屏 `codex` 改为用程序自己的 PageUp/PageDown 翻页，并退出误入的 tmux 历史模式；普通终端和非全屏 Codex 保持原来的滚动方式。
- 开启选择文字后，点击、移动和拖拽仍用于选字，但滚轮不会再被一起屏蔽。
- 触控板的小幅移动会累积，不再每次都跳一整行；各个分屏分别计算，换方向、停顿或连接变化时清掉残余位移。
- 缩放手势不会误传给终端；滚动其他分屏不会抢走键盘焦点。

全屏 Codex 这里是**按页翻阅**，不是像素级平滑滚动。它依赖 Codex 的 PageUp/PageDown 按键，以及 tmux 将前台程序识别为 `codex`；自定义快捷键或启动包装程序可能需要另行适配。已经被程序丢弃的内容不能靠这个修复恢复。本次不会发送提示词、回车或模型请求，也不会修改模型配置。

### 怎么升级？

更新项目后，按原有部署方式重启 **Web 后端**，再刷新网页。只刷新网页不足以加载这次 Python 修改，连接会短暂断开后重连。

保留正在运行的 tmux 会话。重启服务或容器前，先确认它不会连同 tmux 服务和任务进程一起停止；不要删除或重建唯一承载这些任务的容器。

### 怎么验证？

这次不只检查浏览器有没有发出滚轮事件，还用独立的真实 tmux 服务测试全屏与普通屏幕。模拟程序完全离线，不需要账号，不访问用户任务。CI 同时运行 Python、浏览器和 tmux 集成测试；测试命令及依赖见上方英文部分。

发布文件不包含真实会话截图、服务器地址、账号信息或本机恢复备份。
