# 更新与原会话恢复

**简体中文** · [English](UPDATES.en.md)

## 热更新：先装新版，不打断其它窗口

![版本管理](images/updates.png)

1. 先点一下要检查的终端。
2. 点顶部包裹图标，打开“版本与更新”。
3. 点“检测最新版本”，分别看当前窗口、共享安装、官方最新。
4. 只想先安装，就选“仅更新”。所有运行中的窗口都不重启，之后新开的窗口使用新版。
5. 要让当前窗口也用新版，再选“更新并恢复”，读完确认提示后操作。

网页与同一系统用户的 SSH 终端共用配置的程序入口。更新器校验官方发布信息和 SHA-256，下载到暂存目录，离线检查版本和恢复参数，再原子切换入口，不覆盖运行中的程序文件，也不悄悄换到另一套安装。入口不安全、不可写或安装方式不能确认时，会拒绝自动更新；请用原来的包管理器更新后重新检测。

检测由用户触发并带缓存，不会打开网页就强制升级或重启。下载使用受支持的官方发布源，不请求模型接口。网络异常会显示“未确认”，不会把查询失败当作“已经最新”。

## 一键重启并回到原来的交互终端

![原会话恢复确认](images/restart.png)

1. 点会话旁的圆形箭头、终端工具栏的恢复按钮，或版本管理里的“重启并恢复”。
2. 核对工具、目录和原会话标识。较早的 Claude 窗口可能需要先绑定确切的原会话 ID。
3. 确认后，服务端重新核对目标进程和会话，正常退出，等待回到原 Shell，再执行确切的恢复命令。
4. 只有观察到原会话真正加载才算成功。只打印一条命令，或者停在 Shell 显示 `resume`，都不算完成。

支持 Codex、Claude Code、OpenCode，也支持在网页 Shell 里以受支持方式启动的工具。普通 Shell 命令没有通用的聊天会话 ID，不会替你重放。OpenCode 必须能识别到当前选中的对话，停在主页不算。

恢复不重放提问和草稿，不自动发送“继续”，也不靠 `--last`、`--continue` 猜最近对话。参数不支持、目标已变、会话文件不存在或无法确切识别时，操作会被阻止。每个终端有操作锁和请求标识，防止多人同时操作或网络丢响应后重复发送退出、恢复命令。

## 哪些东西真的能保住？

| 情况 | 实际行为 |
| --- | --- |
| 刷新、关标签、断网 | 只分离或重接浏览器连接，tmux 和 CLI 继续运行。 |
| 重启 Web 后端 | 原 tmux 任务保留，网页重新连接。 |
| 仅更新 CLI 安装 | 老进程继续用老版本，新启动的程序使用新版。 |
| 明确重启并恢复 | 所选程序退出后，以新进程打开保存的原对话；正在执行的任务可能被打断。 |
| 服务器重启或 tmux 被杀 | 会话记录可能仍在，但内存和运行中任务不能保住；恢复仍依赖原始会话文件和兼容版本。 |

所以这里的“热更新”不是把旧进程原地换成新代码，不是自动重跑任务，也不保证未来所有版本都一定兼容。

## 失败和回退

- 下载失败或兼容性检查失败，不会主动退出当前任务。
- “安装成功”和“恢复成功”分别记录。如果新版已安装但原会话恢复未确认，请先看原终端，不要连续点；后端也不会盲目重发。
- 较早失败的更新记录可能显示“历史更新未完成；当前安装已更新”，不代表那次历史会话恢复成功了。
- 有可用备份时，“回退安装”只恢复程序入口，不重启现有窗口，也不会回滚新版本写入的会话格式。跨主版本更新会额外确认。
- 升级前备份原生工具自己的配置和会话数据，备份应私密保存。

## 从 v0.1.x 升级网页项目

这次同时改了 Python 后端和带版本号的前端。升级网页项目，与网页里的 CLI 更新器是两件事。

1. 在仓库之外备份源码和私有运行状态，保留旧版标签用于代码回退。不要把凭据、会话文件放进公开压缩包。
2. 用原有服务管理方式只停止或重启 Web 后端，不要停 tmux 或原生工具。systemd 采用示例里的 `KillMode=process`，不要误杀任务。
3. 更新仓库，在虚拟环境中安装 `backend/requirements.txt`，保持原用户、Token、路径和 CLI 入口不变，再启动后端。
4. 刷新页面。已有标签首次导入工作区导航，分屏按设备独立保存。先核对原会话，再按需要明确重启某个工具。

只改前端资源时刷新页面即可；Python 有变化时需要重启后端。项目没有内置的 Git 自动拉取、自更新后台。

## 状态数据不要上传

`CC_WEB_AGENT_RUNTIME_DIR` 保存原会话绑定；`CC_WEB_AGENT_UPDATE_DIR` 保存更新、回退记录和暂存版本；`CC_WEB_WORKSPACE_DB` 保存工作区和布局。这些都是私有运行数据，不是开源示例。文件使用私有权限，会话和更新目录仅属主可访问，不应提交 GitHub，也不要直接打包成问题附件。

项目仍使用共享 Token，持有者基本拥有服务账号的终端权限。更新功能不等于账户自动切换、多租户隔离或 Shell 沙箱。
